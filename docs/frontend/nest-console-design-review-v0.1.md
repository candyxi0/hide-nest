## 1. 设计结论

本轮把“最小治理管理页面”扩展成一套仍然克制、但可直接进入实施的本地治理控制台设计。它不是关窗编辑器，不是数据库浏览器，也不是普通企业运维后台；它只回答五个问题：留下了什么、从哪里来、现在是什么版本、为什么会被找到、我能如何治理它。

视觉母题是“一座会呼吸的档案馆”：温暖纸面承载稳定事实，细窄的粉色脊线表现 revision、证据和关系的变化。主要层级依靠字体、留白、线条与栏宽形成，不依靠大面积圆角卡片或装饰性插画。

## 2. 专家复核

| 维度 | 结论 | 证据 | 后续约束 |
|---|---|---|---|
| 概念一致性 | 通过 | 档案索引、证据线、revision、关系轨迹共用同一语言 | 生产实现不得换成通用 dashboard 卡片皮肤 |
| 信息层级 | 通过 | 左侧全局导航、中部档案索引、右侧详情／治理边界形成稳定三层 | 详情优先级必须高于指标和系统状态 |
| 交互诚实性 | 通过 | 保存与检索分阶段；故障不伪装为空；删除只报告“已接收” | 禁止使用乐观更新宣称不可逆操作完成 |
| 安全边界 | 通过 | 无权不泄露存在性；浏览器无远端 Token；修正返回对话 | 原文库不可形成任意浏览入口 |
| 视觉独特性 | 通过 | 中文宋体式展示字、等宽批注、细线索引、克制粉色 | 禁止 emoji 导航、黑底霓虹、毛绒卡通化 |
| 响应式 | 通过 | 桌面三栏；窄屏列表→详情显式切换；治理动作保持抽屉 | 不把桌面表格强压到手机宽度 |
| 可访问性 | 基线通过 | 语义标题、键盘快捷键、抽屉焦点圈、Escape、live region | 生产组件仍需 axe 与人工屏幕阅读器检查 |

## 3. 浏览器复核与修正

使用本机 Google Chrome 无头模式，通过 Playwright 在 `1440×1000` 与 `390×844` 两种视口复跑：

- 档案列表、详情、搜索、四类导航、六种原型状态均可呈现；
- `/` 可聚焦搜索；治理抽屉起始焦点正确；`Escape` 可关闭；
- 窄屏可由列表进入详情并返回；两种视口均无横向溢出；
- 页面控制台无错误、无未捕获异常；
- 测试首次发现桌面端移动菜单按钮因 CSS 层叠顺序误显示，已提高选择器约束并复跑通过；
- 自动化结果记录在 `prototype/qa-result.json`，可重复脚本为 `prototype/qa/visual-smoke.mjs`。

小林第二轮视觉复核后的定点修正：

- 将四个等权治理按钮重组为“与 hide 一起修正”主动作、归档／隔离并列动作、永久删除独立危险动作；
- 将“来路”改为“证据片段”，明确长对话只展示与当前记忆有关的最小必要片段；
- 将关系、阶段、访问策略和系统状态等可见协议英文改成中文；
- 四个页面顶部大标题统一使用克制的右倾处理，正文与按钮保持正体；
- 浏览器自动化扩展到 44 项并全部通过。

小林第三轮证据阅读复核后的定点修正：

- 详情保留轻量证据预览，并显示当前保存片段数量；
- 新增“查看完整证据”只读层，逐段完整呈现已保存正文、来源、说话者、时间和截取边界；
- 明确“完整证据”不等于整场原对话，前端仍不能扩大服务端给定的证据边界。

小林第四轮多人证据复核后的定点修正：

- 截取边界只有 1 条消息时维持单段原文；
- 截取边界超过 1 条时还原说话轮次，hide 固定左侧、小林固定右侧；
- 对话证据不添加头像、输入框或在线状态，避免把治理控制台复制成聊天产品。

## 4. 保留、修正与快速收益

### 保留

- “正文证据”和“规范记忆”清楚分离；
- 关系变化用轨迹呈现，不把旧事实物理抹掉；
- 归档、隔离、删除具有不同文案、影响范围和完成语义；
- 关窗确认、候选编辑和记忆修正继续回到小林与 hide 的对话。

### 实施时必须补齐

- 使用真实 OpenAPI 生成类型替换原型内数据结构；
- 为分页、刷新、竞态、断线重试和 `Problem Details` 建立组件级状态机；
- 对来源片段做服务端裁剪，前端不得自行请求任意 Payload；
- 完整证据接口必须返回当前授权边界内的全部已保存片段，不能只返回预览字段；
- 删除、恢复和隔离需要 revision／policy revision 条件请求；
- 生产构建必须完成 axe、键盘、屏幕阅读器冒烟及高对比度检查。

### 快速收益

- 先实现只读档案列表／详情和运行状态，可提前验证生成客户端与查询接口；
- 再接归档／隔离，最后接不可逆删除，避免一次把所有风险带入 UI；
- 把原型状态选择器迁移成 Storybook／MSW 场景夹具，而不是带入生产界面。

## 5. 残余风险

1. 精确 npm 版本仍待 HDM-001／002 的 CandidateManifest 构建验证；
2. 新增查询接口尚未进入正式 OpenAPI，必须在 HDM-003／012 中落实；
3. 本地回环控制台的 Origin、Host、启动 nonce 与远端凭据注入必须在 HDM-021／022 安全分析后实现；
4. 当前原型只证明交互和视觉可行，不证明生产权限、数据库或删除链正确；
5. OpenViking 许可证决定不影响本控制台核心实施，但影响未来检索扩展的启用范围。

## 6. 复核判定

判定为 `IMPLEMENTATION_READY_DRAFT`：前端范围、信息架构、交互、技术边界、接口缺口与验收入口均已形成；可以纳入 30 项开发计划。只有实际工程任务、真实契约测试和小林的人类体验验收通过后，才可称为生产实现完成。
