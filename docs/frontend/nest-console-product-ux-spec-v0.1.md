## 0. 文件职责

本文定义 V1 管理界面的产品范围、信息架构、交互、状态、文案、响应式与可访问性要求。它不改变已经确认的记忆语义、状态机、身份与能力边界。

配套文件：

- `nest-console-technical-architecture-v0.1.md`：前端技术、运行位置、安全和构建；
- `nest-console-api-addendum-v0.1.md`：页面真正需要的读模型与 API 补充；
- `prototype/index.html`：只使用合成数据的可交互高保真原型。

## 1. 产品判断

### 1.1 它是什么

nest console 是小林管理长期记忆的个人档案馆。它承担：看清当前规范事实、看清来源是否仍可访问、明确选择治理目标、理解动作影响、观察异步任务结果。

### 1.2 它不是什么

- 不是新的聊天产品；
- 不是关窗候选编辑器；
- 不是让模型自由浏览整座原文库的后台；
- 不是运维监控大屏；
- 不是直接改数据库状态的超级管理员；
- 不是把所有内部表、Token、对象键和故障堆栈暴露给小林的调试器。

关窗仍遵循：hide 在 Codex 对话中提出候选，小林在对话中增删改并一次确认，然后受限工具提交。console 只能显示 ReviewSession 的状态，并把“继续处理”带回对话，不提供第二套确认入口。

## 2. 使用者与使用场景

V1 只有一个人类使用者：小林。hide、整理模型、Worker 和运维服务不是浏览器界面的角色。

主要场景：

1. 想知道系统现在记得什么；
2. 想确认一条记忆来自哪里、是否仍有证据，并阅读系统实际保存的完整证据；
3. 想让一条记忆暂时不再参与普通检索；
4. 想把一条记忆归档，稍后再恢复；
5. 想永久删除一条记忆，并在越过不可逆点前看清影响；
6. 想查看一次保存、索引或删除是否真正完成；
7. 想继续或取消一张仍为 OPEN 的 ReviewSession；
8. 想修正一条记忆——V1 从 console 生成带 ID/revision 的“回到对话修正”入口，不在页面原地覆盖正文。

## 3. 设计立意

### 3.1 一句话概念

**这是一座会呼吸的档案馆：规范事实像纸页一样清楚稳定，来源与变化沿一根偏粉的细线缓慢生长。**

### 3.2 form 推导五问

| 问题 | 答案 |
|---|---|
| 叙事角色 | 工具型档案馆；列表负责定位，详情负责理解，治理抽屉负责做决定 |
| 观看距离 | 主要在 1 米内的桌面／笔记本使用；窄屏只保证完整操作，不追求高密度并排 |
| 视觉温度 | 安静、暖、可靠；危险动作清楚但不恐吓；成功不庆典化 |
| 容量 | 桌面三列最多同时呈现导航、馆藏索引、档案详情；任何确认只保留一个主问题 |
| 视觉母题 | 档案索引、纸页层次、时间脊线与一处不完全规整的粉色批注 |

form 来自“记忆有来路、有版本、有状态、会变化但不能被偷偷改写”这一内容本身，而不是来自通用 AI 产品模板。

### 3.3 视觉语言

- 主背景是偏纸张的暖灰白，不用纯白大面积刺眼底；
- 主文字是暖墨黑；粉色只用于活性标记、选中线和少量批注，不铺成渐变背景；
- 成功用低饱和鼠尾草绿，危险用深砖红；两者都不得只靠颜色表达；
- 少量直角与 4—10px 圆角混用，避免“所有东西都是圆角卡片”；
- 以细分隔线、列宽、缩进和排印建立层级，卡片只在确有独立语义时出现；
- 图标只服务搜索、返回、更多、关闭等操作，不为每个标题配装饰图标；
- 页面进入只有一次编排式动效；日常 hover 不做散乱弹跳。

### 3.4 排印

- display：`Source Serif 4`＋`Noto Serif SC`；用于页面题名和档案正文短标题；
- body：`Source Sans 3`＋`Noto Sans SC`；用于 UI、长文本、表格；
- mono：`JetBrains Mono`；只用于短 ID、revision、时间与 failure code；
- 中文正文基准 16px／1.75；标题 24—42px；说明文字不小于 13px；
- 中西混排时西文字体在 fallback 链前；全局 `font-synthesis:none`、`line-break:strict`；
- 长正文宽度控制在约 32 个汉字，不把详情正文拉满全屏。

## 4. 信息架构

### 4.1 一级导航

| 导航 | 目的 | 核心内容 |
|---|---|---|
| 记忆档案 | 定位与理解规范记忆 | 搜索、过滤、列表、详情、证据、关系、治理动作 |
| 待续确认 | 查看仍 OPEN 的确认单 | 冻结内容摘要、成员数量、打开时间、返回对话、取消 |
| 处理记录 | 判断保存／索引／删除是否完成 | Run 列表、阶段时间线、失败码、重试建议 |
| 系统状态 | 判断本地桥与远端核心是否可用 | Adapter、核心、检索路线、最近同步；不显示秘密 |

### 4.2 路由

```text
/memories
/memories/:memoryId
/reviews
/reviews/:reviewSessionId
/runs
/runs/:runId
/status
```

窄屏保持同一路由，不另做功能缩水版。详情从并排区域变为独立页面，返回后恢复搜索、过滤和滚动位置。

## 5. 页面规格

### 5.1 应用外壳

- 左侧固定导航包含 nest 字标、四个一级入口和“本机连接”摘要；
- 顶部只保留当前页题名、全局搜索或主要上下文，不放无意义指标；
- 远端不可用时出现一条固定故障带，不能把失败伪装为“没有记忆”；
- 浏览器宽度 ≥1180px 时为三列；768—1179px 为折叠导航＋列表／详情双列；<768px 单列。

### 5.2 记忆档案列表

必须显示：

- 当前规范正文的标题或首句；
- `ACTIVE/ARCHIVED`；隔离作为独立派生条件显示；
- memory type、perspective、current revision；
- 最近规范变化时间；
- 来源可访问状态：完整、部分、不可用、未确认；
- 搜索匹配原因只显示可授权字段，不显示被拒对象存在性。

筛选：状态、类型、视角、来源可用性。排序默认按最近规范变化；允许按时间和标题排序。搜索输入按 250ms debounce，URL 保存查询条件；不得把搜索正文写入日志、localStorage 或 URL。

空状态分开表达：

- 真正没有记忆；
- 当前筛选无匹配；
- 检索路线失败；
- 无权查看。

### 5.3 记忆详情

区域顺序：

1. 规范正文与状态；
2. “现在的这版”元数据：type、perspective、validity、uncertainty、revision；
3. 证据片段：来源锚点、消息边界、可访问性与最小必要片段；
4. 变化轨迹：REFINES、SUPERSEDES、CONFLICTS_WITH、PART_OF_TRAJECTORY 等关系；
5. 治理状态：AccessPolicy 摘要、DerivationBlock、当前房间已投递提示；
6. 动作：回到对话修正、归档／恢复 ACTIVE、隔离／恢复隔离、永久删除。

“证据片段”不等于整段原文。即使来源是一场很长的对话，页面也只请求并展示与当前记忆直接相关、足以解释形成依据的最小片段；不把整场对话送到浏览器，不允许前端自行扩展片段边界。详情正文可先显示短预览，但必须提供“查看完整证据”入口，在只读详情层中无截断地展示这条记忆已经保存的全部证据片段，并逐段标注来源、参与者、时间与截取边界。“完整”只指已保存证据的完整呈现，不代表整场原对话。不可用时显示“原文已清理／当前无权／来源暂不可用”，不拼接对象存储路径。

完整证据的正文按消息边界决定形态：边界只有 1 条消息时使用单段原文；边界包含 2 条以上消息时按时间顺序还原为多人对话记录，hide 始终在左侧、小林始终在右侧。该布局只还原说话轮次，不引入头像、在线状态、输入框等聊天产品功能。

所有面向小林的标签、阶段、关系、状态和操作说明使用中文。记忆编号等不可翻译标识可以保留原值，但必须由中文标签引导；协议枚举与失败代码不直接作为主要文案展示。

治理动作采用明确层级：与 hide 一起修正为主动作；归档与隔离为并列的可逆治理动作；永久删除独立放在分隔线下，使用低干扰危险文字样式，避免四个等权按钮随机换行。

四个页面的顶部大标题使用统一、克制的右倾视觉处理；只影响标题，不把中文正文或操作文字合成斜体。

### 5.4 待续确认

- ReviewSheet 必须与冻结 ProposalRevision 逐字一致，UI 不润色；
- OPEN 数量由服务端实时结果显示，不使用本地累加；
- “返回对话继续”只复制／传递 ReviewSession ID 与安全的继续指令，不代表确认；
- “取消确认单”允许对 OPEN 会话执行，终态幂等；
- COMPLETED／CANCELLED／EXPIRED 只读，不出现可执行按钮。

### 5.5 处理记录

用一条纵向时间线表达：

```text
已安全接收 → 决定已提交 → 记忆已保存 → 检索已就绪
```

页面必须使用正式阶段名作为辅助信息，但面向小林的主文案不能只丢出枚举。`CANONICAL_COMMITTED` 后索引失败时，明确写“记忆已经保存，检索尚未就绪”，不能退回“保存失败”。

失败显示稳定 `failureCode`、requestId、是否可重试和受影响范围；不显示堆栈、SQL、对象正文或供应商异常原文。

### 5.6 系统状态

只显示可行动信息：

- 本地 Adapter 是否可用；
- 远端核心是否可达；
- FTS／vector 是否健康或降级；
- 最近一次成功同步时间；
- 当前生产真实材料门是否仍关闭。

不展示 Token、密钥摘要、数据库连接、bucket、内部 IP 或完整环境变量。

## 6. 关键交互流程

### 6.1 归档

1. 小林选中明确 Memory ID＋current revision；
2. 抽屉解释“停止普通检索，可恢复；不等于清理原文”；
3. 一次点击“归档”；
4. 成功后详情状态更新，列表位置按当前筛选决定；
5. stale 时保留页面并要求刷新当前版本，不把旧选择套到新版。

### 6.2 隔离

1. 解释“立即收紧访问，并阻止当前谱系继续派生；不自动删除原文”；
2. 显示对当前房间已投递内容的诚实提示；
3. 确认后先以更严格状态更新；后续派生清理由 Run 追踪；
4. 失败时继续显示隔离保护，不乐观回滚为开放。

### 6.3 隔离恢复

1. 先生成恢复预览；
2. 显示当前 policy、将撤销的临时 block 和仍不会恢复的内容；
3. 预览 revision 未变化时一次确认；
4. stale 重新生成，不能沿用旧确认。

### 6.4 永久删除

1. 先请求 deletion preview；
2. 页面列出闭合范围、共享 Payload、派生物、灾备保留边界、当前房间可能仍含旧内容；
3. 只有一个最终按钮：“永久删除这 N 个对象”；不再叠加复选框、输入短语和第二弹窗；
4. 越过确认点后进入不可取消 Run；
5. FAILED 时全部闭合范围保持隔离，并提供新的重试入口，不伪装完成；
6. COMPLETED 后原目标详情不可再读取，列表消失，恢复系统不得复活。

### 6.5 修正

V1 不在页面原地覆盖 MemoryRevision。点击“与 hide 一起修正”后：

- 生成只含 memoryId、currentRevision 和公开标题的安全引用；
- 复制一段对话指令或打开现有 Codex 入口；
- 新版本仍通过既有 Proposal／Decision／Review 链形成；
- 页面在新 revision 生效后显示变化轨迹。

## 7. 状态矩阵

所有数据页面都必须有以下状态，而不是只有 happy path：

| 状态 | 行为 |
|---|---|
| loading | 保留结构骨架；不使用会被误认成真实正文的灰字 |
| empty | 说明是“无数据”还是“筛选无匹配” |
| denied | 不显示对象标题、正文或存在性细节 |
| stale | 说明对象已变化；提供“读取当前版本” |
| offline | 保留最后一次明确标注时间的只读画面；所有写动作禁用 |
| degraded | 明确故障路线和仍安全可用的范围 |
| failed | failureCode＋requestId＋下一步；无内部异常 |
| success | 克制回执；不使用庆典动画 |

## 8. 文案原则

- 用中文结果说明做主文案，技术枚举做次级证据；
- 不说“删除成功”除非 DeletionRun 已 COMPLETED；
- 不说“没有记忆”来掩盖检索失败；
- 不用“智能”“魔法”“全知”等拟人化夸张词；
- 不用大量感叹号、emoji 和营销话术；
- 危险动作写清“会发生什么／不会发生什么／失败后怎样”；
- `requestId`、revision、failureCode 允许复制，不要求小林手抄。

## 9. 可访问性与键盘

- WCAG 2.2 AA 作为实现目标；正文对比度 ≥4.5:1；
- 点击目标至少 44×44px；窄屏输入字号至少 16px；
- 所有动作可通过键盘完成，焦点顺序与视觉顺序一致；
- Dialog／AlertDialog 打开后正确管理焦点，危险对话默认焦点落在取消；
- 状态变化使用 `aria-live`，但轮询不能不断打断屏幕阅读器；
- 颜色之外同时使用文字、线型或状态标签；
- 支持 `prefers-reduced-motion`；
- E2E 同时使用 axe 自动扫描和人工键盘检查，自动扫描不能替代人工验收。

## 10. 响应式

| 宽度 | 布局 |
|---|---|
| ≥1440 | 导航 216px＋索引 360px＋详情自适应；治理抽屉覆盖详情右侧 |
| 1180—1439 | 导航 200px＋索引 330px＋详情 |
| 768—1179 | 折叠导航；索引与详情二选一或窄双列 |
| <768 | 单列；详情独立路由；底部固定动作只在不遮挡内容时出现 |

V1 不把手机作为主要管理设备，但危险动作、证据阅读和 Run 状态在 390px 宽度仍必须完整可用。

## 11. 原型假设与限制

- 原型全部是合成记忆，不代表小林的真实资料；
- 原型不连接后端、不持有 Token、不写 localStorage；
- “回到对话”只演示复制动作；
- 原型中的网络延迟、stale、denied 和 failure 可通过“原型状态”切换；
- 视觉是实现基线，不是要求生产代码复制原型的 DOM 结构。

## 12. 产品验收清单

- [ ] 小林能在 10 秒内找到一条记忆并判断其当前状态；
- [ ] 小林能区分 ACTIVE、ARCHIVED 和隔离；
- [ ] 小林能看到证据可访问性，但不能任意浏览整库原文；
- [ ] 小林能从预览打开完整证据，逐段看到正文和来源边界，且不会误认成整场原对话；
- [ ] 关窗确认没有在页面被复制；
- [ ] 归档、隔离、恢复和删除的影响没有混写；
- [ ] 删除只有一次最终确认，且影响闭包完整；
- [ ] 保存完成与索引就绪没有混写；
- [ ] denied 不泄露存在性；failed 不伪装为空；
- [ ] 桌面与 390px 均可完成关键流程；
- [ ] 页面不出现秘密、私人真实正文或调试堆栈。
