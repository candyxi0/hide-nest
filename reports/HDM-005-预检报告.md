## 2. 布局裁定：L1R

`L1R` 是唯一推荐布局。它新增 `modules/application` 与 `modules/database-adapter`，使事务入口、跨域编排、数据库迁移、jOOQ 生成物和 jOOQ port adapter 具有单一且可测试的归属。

```text
apps/api ─┐
          ├──> application ──> evidence/memory/runtime/security ports
apps/worker┘

apps/api ─┐
          ├──> database-adapter ──> evidence/memory/runtime/security ports
apps/worker┘
```

规则如下：

- `application` 仅承载跨域 use-case 编排、事务入口与 coordinator；可以依赖四个领域的 domain/port/evidence/memory/runtime/security 表面，但不得导入 jOOQ、JDBC、Flyway、生成类型或数据库适配器。
- `database-adapter` 独占 Flyway migration、jOOQ 配置和唯一生成树；Slice C 才在其中加入 jOOQ port adapter。它只向领域 port 依赖，领域和 `application` 均不得反向依赖它。
- API 与 Worker 可依赖 `application`、`database-adapter` 和领域模块，但二者互不依赖。
- `evidence`、`memory`、`runtime`、`security` 四个领域保持相互隔离；domain/port 是纯层，既有纯度约束不得放宽。

另一候选 `L2D`（分散的接入组织）不推荐：它无法提供唯一事务入口与唯一数据库归属，因此未获选择。

正向架构例：`application` 调用 `evidence` 与 `memory` 的 port，并在一个事务内协调；Slice C 中的 `database-adapter` jOOQ port adapter 实现该 port，并在其内部使用生成类型。反向／禁止例：领域 domain/port 引用数据库适配器，或 `application` 导入数据库适配器、jOOQ、JDBC、Flyway、生成类型，均必须由 Slice D 负向测试拒绝。

| 比较面 | L1R | L2D |
| --- | --- | --- |
| 事务门 | `application` 是唯一跨域入口 | 入口分散，难以证明统一边界 |
| 数据库归属 | `database-adapter` 独占 migration、生成物与 DB port | 归属分散，容易产生反向污染 |
| 领域纯度 | 基础设施可在模块边界被负测禁止 | 纯度风险扩散到每个领域 |
| 实施影响 | 先新增两个模块并调整 API/Worker 依赖 | 表面改动较少，但不能满足裁定约束 |

L1R 的主要风险是新增模块时出现错误依赖；以 Slice A 的依赖骨架和 Slice D 的双向负测降低该风险。它不授权在本次报告中创建这些模块。

| B12 | ACCEPT | 外部迁移；`db.ps1` fail-closed；禁止自动 migrate、repair、clean。 |

### B09 分型细则

候选 `outbox_event` 设计使用 `event_category text COLLATE "C"`，只允许 `GOVERNED` 或 `OPERATIONAL`。`change_event_id` 为可空外键：

- `GOVERNED` 写入（canonical/policy/governance）必须在同一事务内有匹配 ChangeEvent 与 outbox；延迟 aggregate/revision/event guard 在提交前验证三者一致。
- `OPERATIONAL` 写入（closeout received、index complete、route health 等）可以没有 ChangeEvent，但必须恰有一个 run/effect/fact 身份，并具幂等键且无业务 body。
- 类别 `CHECK` 与约束 trigger 共同禁止：governed 缺少 ChangeEvent；operational 伪装成 governed；operational 缺少运行／效果／事实身份；以及跨 aggregate 或 revision 的 ChangeEvent 错配。

正例：policy 变更在同一事务中写入 ChangeEvent 与 `GOVERNED` outbox；索引完成写入带 run identity 的 `OPERATIONAL` outbox。反例一：governed outbox 没有 ChangeEvent 必须失败。反例二：operational outbox 没有 run/effect/fact identity 必须失败。
