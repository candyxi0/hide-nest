# Internal Core↔Cognitive Worker contract v1

These four JSON Schemas describe internal messages, not a public API or generated client. `contractVersion` and `outputContractVersion` remain `nest.worker.v1`. Every object is closed to unknown fields. Core must validate the complete task/result pair, not only each message in isolation: `contractVersion`, `taskRef`, `worldRef`, `taskKind`, and `generation` must match the **attempt envelope that produced the result**; Retrieval additionally matches `targetTurnRef` and `inputVersion`. A newer attempt or an expired lease does not, by itself, invalidate an older attempt's result. While the settlement slot is empty, the first complete result that passes Core's hard checks can win; after settlement, other results cannot occupy that slot. Offline fixtures do not implement attempt settlement.

Retrieval starts from bounded, actual `CURRENT_USER_TURN` text. Optional nearby messages and explicitly maintained anchors are also actual materials, not a generated summary. `sourceExclusion` names source/version/cursor ranges; `deliveredRevisionRefs` names already-delivered Memory revisions. Worker may query only its derived `cognitive_index` for candidate refs and navigation metadata. Core batch-resolves candidates against world, current state, governance, version, and readable scope before any resolved material reaches an Agent or reranker. `selected` is a Worker→Core selection result, not a complete contribution to the main model. Failed Retrieval never carries selected material or candidate half-products.

Formation's `sourceWorkRef` is an opaque, bounded Core-runtime work reference. Core binds it to source identity, progress range, version or short-term snapshot read policy; `READ_SOURCE` may dereference only that bound range. A chat `sessionRef` is optional and does not locate the source. `sourceAnchors` echo that task-bound source identity and version and provide precise locators; they grant no cross-source read authority. Core must accept only Anchors inside the bound source, version, and frozen range, and verify world, Anchor frame/speaker/scope, and expected-current before its formal write entry accepts a proposal. Worker claims alone confer no authority. `SOURCE_INCOMPLETE`, `FAILED`, and `BUDGET_EXHAUSTED` cannot advance a source cursor; the result contract exposes no cursor-advance action. `NO_LONG_TERM_CHANGE` carries neither Evidence body nor a recallable negative conclusion.

Each `WRITE_SET` item has an `itemRef` local to that WriteSet. It denotes the new revision produced if that action succeeds: CREATE yields a new Record's first revision, REVISE yields the old Record's new revision, and SUPERSEDE yields the successor new Record's first revision. It is not a persistent UUID. CREATE forbids `expectedCurrent`; REVISE and SUPERSEDE require its `memoryId` and `revisionId`. `supporting` and `counterExamples` may cite committed `revision:` refs or same-batch `item:` refs. Array order has no relationship meaning. Event, Claim and Quote need a direct Anchor. Understanding may be relation-only, but without a direct Anchor it needs at least one SUPPORT target; a counterexample alone is insufficient. Understanding is a revisable interpretation, never an instruction. The contract contains content, conditions, subject, scope, perspective, uncertainty and evidence refs, with no instruction-priority or personality-lock fields.

The Schema validates these shapes and the exit combinations. S03-B2 Core must fail closed during parsing and transaction validation for the runtime facts Schema cannot prove: WriteSet-wide `itemRef` uniqueness; existence of `item:` targets and absence of self-reference or cycles; no target both SUPPORT and COUNTER; no two change actions for one old Record; revision and memory ownership in the current world and `expectedCurrent` still current; Anchor membership in the task-bound source, version and frozen range; and an eventual SUPPORT path to an Anchor after merging existing relationships. These checks are `RUNTIME_SEMANTIC_VALIDATION_NOT_APPLICABLE_TO_SCHEMA` in the offline tests. `G5-FW-REL-01` remains open until B1 contract and B2 runtime checks pass; this fixture set does not prove a real Worker JSON response or model semantic quality.

Index Projection is derived state. Its generation, manifests, idempotency key, and watermark do not authorize it to decide current, governance, or durable meaning. Agent tool access is bounded to the named Core read capabilities and result submission; the contract grants no arbitrary SQL, shell, URL, filesystem, or database tool. The schemas do not prove candidate relevance, source truth, Core resolution, or any runtime lease/write behavior; those checks are `NOT_APPLICABLE` to this offline contract fixture set.
